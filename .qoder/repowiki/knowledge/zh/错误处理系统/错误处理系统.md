# 错误处理系统

Clawith 智能体协作平台采用了一套结构化的错误处理系统，基于 FastAPI 框架并扩展了标准的 HTTP 异常处理机制。该系统的核心是 `error_contract.py` 文件中定义的标准化错误响应格式。

## 系统架构

错误处理系统主要由以下几个部分组成：

1. **标准化错误对象 (ErrorObject)** - 定义了统一的错误响应结构，包含代码、消息、追踪ID等字段
2. **异常处理器** - 包括 HTTP 异常、请求验证异常和未捕获异常的处理函数
3. **追踪ID中间件** - 为每个请求分配唯一的追踪ID，便于错误追踪
4. **注册函数** - 将所有异常处理器注册到 FastAPI 应用

## 核心文件和包

- `backend/app/core/error_contract.py` - 错误处理系统的核心实现
- `backend/app/core/middleware.py` - 追踪ID中间件实现
- `backend/app/main.py` - 在主应用中注册错误处理器
- `backend/tests/test_error_contract.py` - 错误处理系统的测试

## 架构和约定

### 标准化错误对象结构

错误对象包含以下字段：
- `code`: 错误代码
- `message`: 错误消息
- `trace_id`: 请求追踪ID
- 可选字段：`run_id`, `agent_id`, `stage`, `details`, `retryable`

### 异常处理流程

1. **HTTP 异常处理**: 保留原始的 `detail` 字段，同时添加标准化的错误对象
2. **请求验证异常处理**: 将验证错误作为安全的结构化详情返回
3. **未捕获异常处理**: 记录详细错误信息但不向客户端暴露具体错误文本

### 追踪ID机制

- 使用 `X-Trace-Id` 头部传递追踪ID
- 中间件负责生成或验证追踪ID的有效性
- 所有错误响应都包含追踪ID，便于调试和监控

## 约定和约束

1. **错误安全性**: 内部错误（如数据库密码）不会暴露给客户端，只返回 "Internal server error"
2. **向后兼容**: 保留原始的 `detail` 字段以确保API兼容性
3. **结构化错误**: 支持结构化的错误详情，允许携带额外的上下文信息
4. **追踪ID格式**: 追踪ID必须符合特定的正则表达式模式 `[A-Za-z0-9][A-Za-z0-9._-]{7,63}`
5. **头部传播**: 所有响应都包含 `X-Trace-Id` 头部

该错误处理系统确保了错误信息的一致性和安全性，同时提供了足够的上下文信息用于调试和监控。
